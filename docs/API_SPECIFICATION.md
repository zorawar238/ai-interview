# API Specification

This document provides complete technical specifications for the RESTful and streaming endpoints of the AI Coding Interview Platform.

---

## 1. Authentication & Security Model

- **Session Authentication:** Protected endpoints authenticate via Supabase Auth session cookies (`sb-<project>-auth-token`) managed by `@supabase/ssr`.
- **Edge Proxy:** Incoming requests are routed through `src/proxy.ts` (Next.js 16). Public endpoints (e.g. `/api/health`, `/login`, `/auth/*`) are exempted from session redirection.
- **CSRF & Origin Protection:** Next.js Server Actions and API endpoints enforce strict Same-Origin request headers.

---

## 2. Endpoints Overview

| Method | Endpoint | Auth Required | Description | Response Type |
|---|---|---|---|---|
| `GET` | `/api/health` | No | System health check and uptime probe | `application/json` |
| `POST` | `/api/generate-question` | Yes | Generates structured single technical question | `application/json` |
| `POST` | `/api/chat` | Yes | Live Socratic streaming dialogue with interviewer | `text/plain` (SSE Chunked) |
| `POST` | `/api/execute` | Yes | Isolated multi-language code execution sandbox | `application/json` |

---

## 3. Endpoint Specifications

### 3.1. Health Probe (`GET /api/health`)

Checks server availability, timestamp, and routing viability.

- **URL:** `/api/health`
- **Method:** `GET`
- **Authentication:** None (Public)
- **Response `200 OK`:**
```json
{
  "status": "ok",
  "message": "AI Coding Interview Platform API is running.",
  "timestamp": "2026-10-22T22:30:00.000Z"
}
```

---

### 3.2. Single Question Generation (`POST /api/generate-question`)

Generates a schema-validated technical coding question with progressive hints and evaluation criteria.

- **URL:** `/api/generate-question`
- **Method:** `POST`
- **Headers:** `Content-Type: application/json`
- **Request Body:**
```json
{
  "topic": "System Design",
  "difficulty": "medium"
}
```

- **Validation Rules:**
  - `topic`: `string` (required, non-empty)
  - `difficulty`: `'easy' | 'medium' | 'hard'` (required)

- **Response `200 OK`:**
```json
{
  "question": "Design a distributed rate limiter supporting 10,000 requests per second across 5 regional clusters.",
  "hints": [
    "Consider token bucket or sliding window log algorithms.",
    "Think about Redis key synchronization and network latency overhead."
  ],
  "expectedConcepts": [
    "Sliding Window Counter",
    "Redis Sorted Sets",
    "Race condition handling via Lua scripts"
  ]
}
```

- **Error Responses:**
  - `400 Bad Request`: `{"error": "Topic and difficulty are required"}`
  - `500 Internal Server Error`: `{"error": "Failed to generate question. Is Ollama running?"}`

---

### 3.3. Socratic Interviewer Streaming Chat (`POST /api/chat`)

Streams progressive conversational responses from the Principal Engineering Interviewer persona via chunked HTTP stream.

- **URL:** `/api/chat`
- **Method:** `POST`
- **Headers:** `Content-Type: application/json`
- **Request Body:**
```json
{
  "messages": [
    { "role": "user", "content": "Should I use a Hash Map or a Binary Search Tree for constant time lookups?" }
  ],
  "questionContext": {
    "role": "Senior Backend Engineer",
    "topic": "Algorithms",
    "difficulty": "medium",
    "prompt": "Implement an LRU Cache with O(1) get and put operations."
  },
  "currentCode": "class LRUCache { constructor(capacity) { ... } }"
}
```

- **Response `200 OK`:**
  - `Content-Type: text/plain; charset=utf-8`
  - `Transfer-Encoding: chunked`
  - Transmits progressive Markdown text tokens as generated by the local LLM.

- **Interviewer System Rules:**
  - Strictly prevents providing full code solutions to candidates.
  - Asks clarifying questions and delivers targeted Socratic guidance.
  - References the candidate's current working code and architecture notes.

---

### 3.4. Isolated Code Execution Sandbox (`POST /api/execute`)

Executes candidate solution code inside a process-isolated temporary workspace with hard timeouts, memory bounds, and stripped environment variables.

- **URL:** `/api/execute`
- **Method:** `POST`
- **Authentication:** Required (Supabase session)
- **Headers:** `Content-Type: application/json`
- **Request Body:**
```json
{
  "language": "typescript",
  "code": "console.log('Result:', 40 + 2);",
  "stdin": ""
}
```

- **Supported Languages:**
  - `typescript`: Run via Node.js native `--experimental-strip-types`
  - `javascript`: Run via Node.js ESM (`.mjs`)
  - `python`: Run via Python 3 unbuffered (`python -u`)
  - `sql`: Run via in-memory SQLite runner script pre-populated with employee schema

- **Execution Limits:**
  - **Hard Timeout:** 5,000 ms (Kills subprocess and process tree via `SIGKILL` / `taskkill`)
  - **Output Cap:** 64 KB maximum stdout/stderr buffer to prevent memory exhaustion
  - **Payload Size:** Max 50 KB code payload enforced via Zod

- **Response `200 OK` (Execution Success):**
```json
{
  "stdout": "Result: 42\n",
  "stderr": "",
  "exitCode": 0,
  "executionTimeMs": 142
}
```

- **Response `200 OK` (Execution Timeout):**
```json
{
  "stdout": "",
  "stderr": "Execution timed out (limit: 5000ms). Check for infinite loops or blocking I/O.",
  "exitCode": -1,
  "executionTimeMs": 5003
}
```

- **Error Responses:**
  - `400 Bad Request`: Payload validation error (unsupported language, payload exceeding 50 KB).
  - `401 Unauthorized`: Missing or invalid session credentials.
  - `500 Internal Server Error`: Execution environment bootstrap failure.
